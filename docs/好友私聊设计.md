# 好友私聊设计

## 入口与布局

大厅和房间共用右侧好友列表，每位好友旁显示“私聊”，房间阵营成员行不重复放私聊入口。点击后在右下角打开独立面板。面板左侧列出全部好友会话，可切换对象；右侧以左右对话气泡显示历史、加载更早消息和发送框。对方在左、自己在右，每条消息旁预留头像框，当前用昵称首字占位。输入框右侧的表情按钮可打开滚动面板。离线好友也可留言。未读消息在好友入口和对应会话标签显示闪烁绿点，点内显示未读数量；打开该好友记录后标记其全部未读消息，绿点消失。自己发出的每条消息在气泡外、靠聊天区域中间的下角显示“未读 / 已读”。

## 数据与权限

私聊消息保存在账号 SQLite 数据库的 `private_messages` 表，按双方账号 ID 组成的规范顺序存储。每条包含 ID、发送者、正文、发送时间与已读时间。读写接口均核查当前好友关系，非好友不能查看或发送。正文为 1–500 字纯文本，拒绝控制字符；页面以文本节点展示。

`GET /api/social/messages/:accountId?before=游标` 每次返回最多 50 条，按写入顺序展示，并给出下一页游标。`POST /api/social/messages/:accountId` 发送消息。发送后通过现有 WebSocket 向双方在线客户端推送 `private_message`，离线时历史保留，下一次打开会话可查看。

好友列表返回每位好友的未读数。`POST /api/social/messages/:accountId/read` 将该好友发给当前用户的所有未读消息标为已读，并通过 WebSocket 向发送方推送 `private_read` 事件，更新逐条已读状态。

删除好友时，在同一事务中删除好友关系与双方私聊历史。双方当前打开的会话收到好友关系变更后关闭；再次成为好友时从空历史开始。

## 验收

1. 大厅和房间均能从好友入口打开同一会话；切换好友显示各自历史。
2. 双方在线时发送后实时显示；一方离线后重新进入仍能查看历史。
3. 非好友无法通过接口读取或发送私聊。
4. 删除好友后双方历史均不可见；重新加好友后历史为空。
