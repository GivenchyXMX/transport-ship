# 房间文字聊天设计

## 目标与范围

房间成员在房间页和对局内发送文字与 Unicode 表情。新成员进入时获取当前房间最近 50 条可见消息；房间解散后消息消失。不做私聊、持久化或自定义图片表情。

## 交互

- 房间页阵营列表下方放紧凑的“房间聊天”，可切换“队伍 / 全体”，显示时间、昵称和正文；消息区域固定高度并独立滚动。全体消息按发送者阵营着色：保卫者蓝色、潜伏者黄色，对局内同样适用。聊天和房间操作按钮保持可见，较小屏幕下房间详情区域独立滚动。
- 输入框最多 200 字；按 Enter 或点击“发送”提交。空白消息不发送。点击“表情”按钮打开可滚动的表情面板，选择后插入输入框。
- 本地先显示“发送中”；服务端回传后确认，5 秒无回传则显示发送失败，方便发现服务端尚未更新等问题。
- 收到新消息时追加到列表并滚至底部。加入房间时展示服务端下发的最近消息。
- 离开、被踢或断线后清空本地消息；重新加入以服务端历史为准。
- 对局内左下角显示最近消息；Enter 打开输入，默认“队伍”，按钮可切换“全体”。输入框右侧的表情按钮打开可滚动面板，选中后插入光标位置。有内容时 Enter 发送并重新锁定鼠标；空白内容按 Enter、按 Esc 或点击画面重新锁定鼠标，均取消输入并清空未发送内容，不触发暂停。输入时本机操作键失效，但游戏计时和其他玩家行动继续。

## 协议与数据流

沿用现有 `/ws` 登录连接，服务端以 `player.room` 确定房间，不信任客户端提交的房间 ID 或昵称。

| 方向 | 消息 | 内容 |
| --- | --- | --- |
| 客户端 → 服务端 | `chat` | `{t:"chat",text:string,channel:"all"|"team",clientId:string}` |
| 服务端 → 新成员 | `chat_history` | `{t:"chat_history",roomId,messages:[...]}`，在 `room` 快照后发送 |
| 服务端 → 对应频道成员 | `chat` | `{t:"chat",message}`，包括发送者 |

每条 `message` 包含服务端生成的 `id`、`roomId`、`netId`、`name`、`text`、`sentAt`、`channel`、`team`，并回传客户端 `clientId`。全体消息发给房间所有成员；已选阵营的成员可在房间和对局中发送队伍消息，只发给发送时同阵营成员。入房历史也按接收者阵营过滤。房间对象只在内存中保留最多 50 条；历史不写入数据库。服务端接受去首尾空白后 1–200 个 UTF-16 字符的纯文本，拒绝控制字符，并限制每个连接每秒最多一条。客户端使用文本节点展示正文和昵称。

## 验收

1. 两个账号进入同一房间，任一方发送后双方都只看到一条消息；其他房间看不到。
2. 第三人加入后看到最近 50 条，且顺序与发送顺序一致。
3. 空内容、超长内容、控制字符、1 秒内重复发送均被服务端拒绝。
4. 离房、被踢、断线清空本地记录；重进房间按该房间历史展示。
5. 昵称和消息中的 HTML 特殊字符显示为普通文字。

## 后续扩展
