# 地图碰撞数据契约

## 当前边界

运输船的共享规则在 `shared/maps/transport-ship.json`：地图 ID 和版本、边界、出生点、导航网格、雷达与 bot 路线由客户端和服务端共同使用。客户端详细场景及碰撞体由 `src/client/maps/transport-ship/scene.part.js` 构造；服务端弹道遮挡使用 `server/maps/transport-ship.js` 中的 145 个简化盒体。两端的碰撞体目前不是同一份数据，不能把“地图规则共用”等同于“全部物理一致”。

| 对象 | 客户端 | 服务端 | 扩图约定 |
| --- | --- | --- | --- |
| 玩家移动 | 场景世界 `gr` 的碰撞体与寻路网格 | 房间边界、速度和穿越校验 | 主要墙、箱体、地面位置应对齐；小装饰可仅在客户端存在 |
| 枪、刀和手雷遮挡 | 场景射线与武器反馈 | `combat.wallDistance` 等权威射线 | 对真人造成伤害的遮挡，以服务端为准；主要掩体不能出现明显相反结果 |
| 窗口和通道 | 可阻挡移动但允许子弹通过的碰撞体 | 对应窗口段不加入弹道遮挡盒体 | 不能用一个 `solid` 值同时表达移动和弹道语义 |
| 出生点 | `rules.spawns` | 同一份规则投影为 `[x,y,z]` | 两队坐标、朝向与地图边界均须校验；还需人工检查不陷入几何体 |
| 雷达和 bot | `rules.radar`、`rules.bot` 与客户端碰撞世界 | 不运行雷达和 bot AI | 路线点必须在导航边界内，实际可达性需要场景检查 |

## 新地图的数据要求

1. 在 `shared/maps/` 增加唯一 ID 和正整数版本的规则；边界、两队出生点、导航、雷达及 bot 路线先通过 `validateMapRules`。
2. 客户端地图包创建视觉场景和移动碰撞体，明确每个特殊碰撞体是否阻挡玩家、子弹、视线；实现加载、菜单预览和释放所需的地图钩子。
3. 服务端地图包给出弹道遮挡体和与共享规则完全一致的出生点。旋转盒体统一用中心坐标、半尺寸 `hx/hy/hz`、水平旋转的 `c/s` 表示；尺寸必须为正。
4. 为典型视线建立白盒射线样本：两队主通道、箱体正后方、窗口、侧路及地图边界。人工验证实际移动、跳跃、穿窗射击和出生位置。
5. 房间选图阶段必须让房间锁定地图 ID 与版本，并让服务端每次位置、出生和命中裁决按该房间地图取数据。当前代码只注册运输船，尚不提供选图协议。

当前自动检查会守住运输船的 20 个出生点、145 个服务端碰撞体指纹和代表性射线结果。它不能证明客户端所有几何与服务端完全等价；发现差异时按上表的语义逐项修正。
